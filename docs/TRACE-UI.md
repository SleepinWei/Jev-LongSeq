# Trace Studio 实现与验证

日期：2026-09-27。

## 复用范围

直接复制 Jev Ultrafast 的 `style.css` 为 `src/jev_browser/static/ultrafast.css`；复用其浏览器预览框、侧栏、动作轨迹布局、DOM 转义与渲染模式，以及标准库本地 HTTP 服务的 Host/Origin/token 保护方式。适配本项目的运行目录、typed trajectory、规划契约、证据和结果数据。

源项目未修改，无运行时跨项目依赖，没有复制 `.env` 或模型密钥。MIT 许可和来源声明分别保留为 `static/ULTRAFAST-LICENSE.txt` 与 `static/NOTICE.md`。前端使用原生 HTML/CSS/JS，无 npm 安装或构建步骤。

## 功能

- 自动发现 runs 目录中的历史运行；默认优先展示最近成功的 Jev 记录。URL 的 `run` 参数可直接定位一项运行。
- 展示实际动作数、独立判分、覆盖、保存集合数量、耗时和模型调用账本。缺失结果、usage 或价格保持未知，不补造数据。
- 搜索/筛选动作、模型选择、规划与纠正、子任务完成、抽取、写入读回及错误；按事件前进后退、拖动时间线、以原始时间间隔 1× 回放。
- 检查所选时间点的候选、选择置信度、规划 DAG 的依赖和完成状态、字段值及来源引用、原始 JSON。
- 读取已有 `trace.zip` 内的真实截图，按 Playwright wall clock 与 JSONL 时间戳对齐；支持 `file` 和旧版 `sha1` 引用。不在文件系统解压归档，不把 DOM 文本伪装成网页画面。
- `--live-preview` 为 Playwright / BrowserGym 后端开启连续 JPEG 截图。采集间隔 0.5 秒加截图耗时；前端约每秒取最新帧。模型等待期间仍可更新。截图不进入模型上下文、不消耗动作或环境步，截图耗时计入墙钟。
- 实时心跳过期或结果落盘后停止标记 LIVE，结束后转为归档回放；没有过程截图时明确标记最终截图。
- 一键启动 12 条记录的本地规则演示，不调用任何真实模型。支持直接输入 prompt，运行本地目录样例或自定义网址；使用 Jev + 页面所选规划模型（Codex / 已配置 API），自动跟随画面并展示最终回答。也可跟随 CLI 启动的任务。
- 轨迹导出；本地 API 使用运行目录索引和资源白名单，拒绝跨目录访问、目录外符号链接和跨站启动请求。

## 使用

```bash
.venv/bin/python -m jev_browser.inspector --runs runs --port 8768 --env-file /path/to/your.env
# 或在 uv 同步安装后：
uv run jev-trace --runs runs --port 8768 --env-file /path/to/your.env

# 另一个终端运行；输出路径应位于查看器的 runs 根目录内
.venv/bin/python -m jev_browser demo --records 12 --live-preview --output runs/live-demo
```

当前服务在 macmini 使用 `http://127.0.0.1:8768`，通过 SSH 隧道访问；8767 属于其他应用。Codex 按需读取摘要和部分报告的方法见[实验诊断文档](EXPERIMENT-DIAGNOSTICS.zh-CN.md)。以下历史验证章节中的旧端口仅记录当时情况。

输入 prompt 或点击“填入示例 prompt”后点击“运行 prompt”即可启动真实模型任务；任务预算为 300 秒、150 动作、40 次反馈调用。可选择目录样例（1–100 条）或 http/https 起始网址。自定义目标的 `strict_success` 保持未知，不用固定样例判分器评价不同的目标。查看/回放已有记录不会调用模型，规则演示也不会调用模型。启动错误显示在表单旁，完成后显示回答及停止原因。

## 边界

预览为只读网页截图，不提供远程手动点击或 iframe 控制。历史录像是 Playwright 采样帧，不能保证每个动作都有独立图像；时间线使用该时刻最近的已录制帧并显示截图时间。未开启预览的正在运行任务只能跟随事件，待 trace.zip 完成后才能回放网页画面。

实时截图增加渲染与 I/O 开销，性能对照应统一预览开关。服务仅面向本机，不是公开部署的多用户系统。截图、DOM 和轨迹仍可能包含任务数据；服务不会发布这些内容到外部网站。

## X 搜索耗时优化（2026-09-27）

以 `ui-prompt-1790498111017937000/task` 为基线：三词搜索端到端 126.3 秒，页面观察 52.9 秒，19 次动作尝试中 10 次因页面变化被拒绝，3 个搜索词调用输入助手 8 次。

实现调整：

- Playwright / Chrome 在一次同步 DOM 读取中同时绑定可见控件与页面快照，保留一个远程对象，执行时才取得目标节点。观察不再为全页控件建立并逐个释放远程句柄。
- 动态任务的搜索控件（原生 search 输入或 role=search 区域）允许无关页面内容变化；仍核对目标节点身份、索引、可见控件属性、上下文、URL、标题、弹窗及新出现的验证页面。其他写操作维持全页校验。动态 wait 不因页面自然更新而被判为过期。
- 仅对未执行的 stale 输入重试复用用户目标中原有的字面文本；目标值、阶段指导或页面位置变化即失效，成功或未知执行结果清空缓存。从网页推导出的值不缓存。
- 新增 browser.snapshot、browser.snapshot_read、browser.release_handles 子阶段耗时；这些阶段包含在 browser.observe 中，不能重复相加。

回归覆盖搜索外的页面变化、控件替换、标签/值/上下文变化、弹窗、验证提示、导航，以及未知写入不得通过缓存重试。

实测还发现阶段反馈已确认填入成功，但控制器未消费该确认，导致策略继续等待尚未提交的搜索结果。现在阶段反馈的 confirmed 会经过原有新鲜状态检查后解除 pending，并为 fill/select 明确设置原子动作的读回目标。填入成功不代表已提交或任务完成，最终仍需单独复核。

首次优化复测 `ui-prompt-1790498861606176000/task` 在读回阶段停止（needs_attention），保留作诊断记录，不计作成功提速样本。

完整复测 `ui-prompt-1790499065050543000/task` 已成功，轨迹依次观察到三个查询的搜索结果页，最终语义复核通过（无独立判分）。页面已展示完成记录。

## 减少 DS 的确定性输入与阶段开销

动态候选会从用户目标中的成对双引号、中文双引号或「」提取最多 16 个不同的原文值，记录 Python 字符串起止位置。由 Jev 选择对应的可见字段和值；不会自动按词序填写，不从网页指令提取可信绑定。SELECT 只提供当前可见选项中存在的原文值。来源不明确、需要转换或推理的内容仍保留通用输入助手候选。直接绑定记为 input_binding/source=user_prompt_quote，不计作 DS 请求。

普通 initial/step/stage_budget 且没有待确认动作时，DS 只返回 next_goal 与 working_memory。反馈输入移除重复的当前证据文本和证据增量；原始观察仍照常归档。待确认动作、异常诊断和最终完成复核保留完整 schema、证据校验和单次修复流程；简版 schema 拒绝夹带 complete 字段。

阶段窗口仍默认 12，但按 receipt=ok 的非 WAIT 动作计数。stale/rejected/unknown 与纯等待不推进窗口；所有动作尝试仍消耗全局 max_actions/max_cycles，避免无限重试。轨迹保留 effective_actions/attempted_actions 和两种阶段计数。

验证中 `perf-user-bindings-01` 的输入助手为 0 次，但观察到搜索顺序为 Tibo Reset → Spark Labs → Zhen Fund → Tibo Reset；虽被语义模型标记 success，验收不通过，不算合格提速样本。后续指导明确区分填入、提交与结果观察。`perf-user-bindings-02` 在首次观察因 iframe 检查停止，未调用模型。Playwright/Chrome 的 iframe 检查现按可见框架判断；可见 iframe 和验证提示继续拦截，后台隐藏 iframe 不阻塞主页面。

最终复测 `perf-user-bindings-03`：端到端 43.75 秒，控制器 40.83 秒；观察 0.43 秒，15 次 Jev 请求，3 次 DS 反馈/复核请求，2 次 DS 输入请求，共 20 次 HTTP 请求且均成功。完整 DS 请求数从上一合格样本的 9 次降至 5 次，输入助手从 4 次降至 2 次。原始基线则为 12 次 DS、8 次输入助手。仍有两次选择通用输入助手，未宣称完全消除输入调用。

运行后额外根据观察 URL 独立检查查询顺序，得到 Spark Labs → Zhen Fund → Tibo Reset；验证记录见运行目录 `search-order-check.json`（只验证顺序，不是搜索内容的独立判分）。本次总耗时较上一合格样本 85.26 秒减少约 48.7%，较原始 126.28 秒减少约 65.4%。单次实站数据受网络、页面与模型路径影响，不作为平均性能结论。

测试：原文绑定、阶段计数、动态控制与模型接口相关 81 项通过；后续 iframe 与观察阶段兼容回归的失败断言已修正并补验通过，保留新增的 DOM 等待计时，不覆盖其他任务的导航改动。

## 模型连接失败诊断（2026-09-27）

`ui-prompt-1790500567184234000/task` 端到端 42.30 秒，浏览器动作数为 0。
自动选址的 DS 请求前两次连接失败，第三次成功；首次阶段指导的三次尝试全部
`ConnectError(EndOfStream())`。六次 HTTP 尝试共 33.73 秒（包含重试退避），其中
五次失败。这次没有进入 Jev 决策或搜索操作，不能归因于搜索字段 stale 或网站拒绝访问。
前一个 `ui-prompt-1790500455250193000/task` 则有 15 次请求、10 次连接错误，
失败尝试及退避累计 56.9 秒，占端到端 81.5 秒的大部分；另有一次 stale 填写。

本机 Clash TUN 使用 Fake-IP；两个 API 域名的流量均经过该网络路径。
Clash 的 `service_2026-09-27_17-12-54.log` 记录 DS 命中直连规则后，
上游地址连接超时。后续日志也记录 Jev 所用代理节点的上游连接超时。
无鉴权探测观察到本机 TCP 已建立、TLS 阶段被关闭，与 Python 的 EOF 类错误相符。
显式改走现有 Clash HTTP 入口仍能复现，因此没有将它当作已验证修复，也没有修改全局路由。

应用侧将自有 HTTPX 客户端的空闲连接保留时间由默认 5 秒延长到 120 秒，
减少交替等待 DS / Jev 时的重复握手；保持原有两次重试、证书校验及外部注入客户端的所有权。
每次请求新增目标主机、TCP/TLS/请求发送/响应头阶段耗时、失败阶段和异常类型链；
不记录 trace 内容或异常原文。最终 ConnectError 包含服务、阶段和尝试次数，避免空白报错。
连接复用只能降低重新建连频率，不能修复不可达的代理节点或首次连接失败。

17:30 的两次无有效密钥根路径探测均成功完成 TLS，DS 返回 401，Jev 返回 404，
分别耗时 2.33 / 2.44 秒。原始记录为 `runs/network-diagnostic-20260927.json`。
这些 HTTP 状态仅证明当时收到服务响应，未验证有效密钥、模型推理或完整任务恢复，
也不能证明间歇性网络故障已经消失。

本次回归：模型传输、可观测性、动态控制、输入绑定共 49 项通过，修改文件的 Ruff 检查通过。
本地 HTTP 服务验证了空闲 6 秒后仍使用同一连接；故障注入验证重试上限、逐尝试记录隔离、
异常阶段诊断、敏感数据脱敏，以及注入客户端不被关闭。

## 小红书搜索图标与 DOM 预览标注

`ui-prompt-1790501451315254000/task` 停在 `readback unresolved; no resubmission`，
16 次动作尝试后仍在 `/explore`。轨迹填写过 `Spark Labs`，却点击无名称按钮，
未观察到搜索结果 URL。当前页面 DOM 的同一区域包含添加附件的原生按钮（SVG `#addM`）
和真正的搜索提交控件（嵌套 div + 空 alt 图片 `standardSearchIcon…svg`）。
旧版搜索入口则为 div + `alt="搜索"` 图片。原来的原生/ARIA 控件选择器遗漏 div 搜索入口，
无文字按钮又无法区分用途，导致候选不足和错误点击。

现在补充可见、可点击的自定义控件，合并继承指针样式的装饰子节点；名称优先使用
可访问标签、可见文字、图片 alt / title，最后从图标资源和类名提取限定词表提示，
明确标为 `search (icon control)` / `add (icon control)` 等。这些提示仅是未受信任的描述，
不扩大动作权限。隐藏、inert、禁用、替换节点与页面状态变化的检查继续生效。

Live Preview 增加 DOM 标注开关、元素编号、输入框样式和对应观察下的选中动作高亮。
几何信息仅用于预览，不加入模型输入或页面版本指纹。截图前后核对绑定节点几何，
布局或文档改变时丢弃该帧标注；每个归档帧携带自己的坐标和 observation_id，
实时显示也读取对应的不可变归档帧。旧 run 没有坐标时明确显示未记录标注。

## 搜索结果出现后持续 WAIT 的修复

`ui-prompt-1790504032435816000/task` 已显示查询结果，但后续重复提交同一搜索，
最终在第 35–39 轮连续 pending 后退出。搜索按钮之前继承整段阶段目标，
把确认搜索执行与找到相关传闻混在一起；整页语义变化又会改变动作去重键。

现在只对名称明确为搜索、且同一最近容器内有唯一可见编辑框的按钮记录
`search_query` / `search_scope`。有多个编辑框或密码字段时不作这种绑定。
空查询不提供提交候选，避免填写 stale 后误搜轮播 placeholder。
搜索提交的核验目标限定为当前查询的可见结果列表或明确无结果提示，
不要求结果相关或整项研究完成；仅 URL 改变、输入框值或空容器不构成确认。
Jev 与阶段复核提示均明确这一区分。

搜索去重键使用标签页、站点、字段范围和实际查询，排除无关结果列表、通知及元素编号变化。
同一查询已执行或结果未知时不再提交；仅 stale/rejected 的未执行尝试允许重试，
不同查询仍可提交。其他按钮维持原来的动作键和保护。
连续两次搜索 pending（若等待预算更小，则在其上限）触发一次 `search_readback`
完整复核；确认后重新决策，丢弃旧候选。复核未知则停止，仍 pending 则遵守原等待上限。
等待动作记录查询和当前等待次数。未把点击回执或页面任意变化自动当成搜索成功。

同时限制图标提示读取范围：普通链接的导航 URL 不参与图标命名，避免
`xsec_source=pc_search` 等参数让无标题结果链接被误标为 search 图标。

本地回归覆盖稳定去重、改词、空值、未执行/未知回执、相关性无关的执行确认、
明确无结果、加载/未知/无变化停止、一次复核上限及 DOM 唯一字段绑定。
