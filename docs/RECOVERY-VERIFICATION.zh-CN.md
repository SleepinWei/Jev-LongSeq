# 失败恢复修复与本地验证

日期：2026-09-27。针对 [两次试跑失败分析](FAILURE-ANALYSIS.md) 中的证据缺失、同 URL 记忆覆盖、重规划反馈不足和 Plan 格式异常完成修复。本轮没有新增真实模型调用或公共 benchmark 任务。

后续用户要求的真实模型复验已完成，见 [真实模型复验报告](RECOVERY-PILOT.zh-CN.md)：首次连接失败，补跑同一 32 条任务通过严格判分。本文保留此前本地测试阶段的记录。

## 实现变化

1. **可配置的确定性证据抽取。** 新增可信任务选项 `extraction.capture_on_observe`，通用任务默认关闭、目录任务默认开启。完整且无歧义的实体及白名单字段出现后，控制器执行真实 `extract_visible` 动作；回执成功后才写入带来源的事实。同视图相同证据不重复自动抽取，部分字段或加载中页面不强行抽取。遵守当前操作权限、动作预算与子任务预算，所有策略/调度模式使用同一机制。
2. **实体进度与视图记忆。** 由可信任务中可分离的实体事实条件计算 `unseen / observed / evidence_recorded / pending_write / verified`、缺失字段和下一条未验证实体，提供给 Jev、生成式策略和规划器。跨实体 OR/NOT 不强行拆分，进度提示不替代最终验证。页面摘要按 URL、标签、frame、文档版本保存，最多保留 8 个视图；近期动作增加描述、实体、目标引用和前后观察标识。
3. **诊断驱动重规划。** 提供当前契约、已完成子任务、未满足谓词、实体进度、近期动作和已用动作数。未满足的 AND 可拆开报告，OR/NOT 保留整体以免把可选条件误写成必需条件。提示规划器优先按单个可验证实体拆分，而不是仅增加预算；这是规划引导，不是对模型分解质量的保证。
4. **有界 Plan schema 纠正。** 每次规划最多追加一次纠正请求，并占用同一个 `max_planner_calls` 预算。HTTP 尝试和 tokens 进入原有账本，纠正调用标记为 `planner_repair`。无效计划不执行、不静默删字段；修正后的计划仍接受权限与绑定验证。轨迹保存错误位置、响应哈希、经过已知密钥及常见凭据字段遮蔽的有限响应片段。

主要实现位于 `src/jev_browser/controller.py`、`memory.py`、`models.py`、`protocol.py` 和目录任务配置 `fixture.py`。规划器扩展接口增加可选关键字参数 `feedback`，自定义规划器需要接受该参数。

## 验证结果

最终完整回归：

```text
$ .venv/bin/pytest -q
54 passed in 33.81s

$ .venv/bin/ruff check src tests
All checks passed!

$ .venv/bin/ruff format src tests
21 files left unchanged
```

新增 12 个测试实例位于 `tests/test_recovery.py`，包括：

- 在 flat / once / event 三种模式下，故意不主动抽取的脚本策略仍可通过 3 条记录的真实本地浏览器流程；第一条符合条件保存并读回，第二条无需保存也能完成证据记录，随后推进第三条。独立目录判分通过。
- 同 URL 的列表/详情不会立即互相覆盖，视图缓存保持 8 条上限；仅观察不直接写入事实。
- 自动抽取要求完整、无歧义字段，默认由可信配置显式开启；计入动作预算，拒绝过期回执，不扩大契约权限。
- 区分“已看过”“已有证据但未完成”“已验证”；跨实体 OR 不错误拆解为独立目标。
- mock HTTP 验证一次纠正成功、纠正仍失败、总预算不足时的退出行为；两次请求都计入次数和 tokens；已知测试密钥不出现在轨迹或纠正反馈中。
- 重规划确实收到未满足条件、当前契约、实体进度和有语义的动作记录。

首次浏览器测试被 macOS 沙箱的 MachPort 权限限制阻止，获得工具执行授权后使用隔离 Chromium 完成。随后测试发现，读回与等待连续执行时部分动作缺少下一次观察标识，修复后完整套件通过；同一观察间隔内多个动作以 `intervening_actions` 标记，不声称存在未采集的中间快照。

## 结果边界

这 54 项是机制与回归测试，模型响应使用测试替身。历史两项真实模型 pilot 仍为失败，本轮没有第三项真实模型重跑，因此不能声称 Jev 已能完成长任务，也没有新的公共 benchmark 分数。

后续真实模型复验应使用新的空输出目录，保留当前任务配置、源代码 hash 和全部调用账本。目录任务新增自动抽取与进度输入，不能把修复前后的结果当作只有模型差异的严格对照。原始运行产物及旧报告保留不改写。

普通网页的语义抽取仍需单独适配。网络连接稳定性、供应商严格 schema 输出支持，以及提示与上下文 token 开销尚未通过新真实模型运行验证。
