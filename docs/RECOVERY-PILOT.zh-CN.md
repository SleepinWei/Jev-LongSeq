## 修复实际发挥的作用

1. **证据与实体推进已在真实链路中生效。** 32 次自动抽取覆盖全部实体，另有 7 次写后读回，共 39 个抽取动作，全部计入 116 个动作。item-002 抽取后只返回一次，修复前则返回了 31 次。
2. **格式恢复确实遇到并处理了原故障。** 初始规划再次包含多余的顶层 `type` 字段；严格校验拒绝后，系统进行一次预算内纠正，得到合法的 32 个实体子任务。两个请求均计入规划次数和 tokens。随后全部 32 个子任务完成，没有因停滞或子任务预算耗尽再次重规划。
3. **执行接近参考动作长度。** 原参考 H=115；成功运行 116 个动作，比参考多最后一次返回列表。77 次点击具体为 32 次打开详情、32 次返回、6 次翻页和 7 次保存，没有此前的重复往返循环。

## 连接故障与成本不能忽略

本轮首次尝试的初始规划请求连续 3 次连接失败，异常为 `ConnectError(EndOfStream())`，未进入策略执行。随后只做了无凭据 HTTPS 连通性检查，两个模型服务均恢复 HTTP 响应，再启动一次同配置补跑。

补跑中 Jev 有 79 次 HTTP 尝试、78 次成功，其中一次连接错误重试后恢复；成功响应均返回 `jev-1.13.0`。初始规划和纠正规划各一次 HTTP 成功。

本轮两次尝试合计端到端 **213.52 秒**；已返回的 usage 合计 **764,069 输入 / 44,508 输出 tokens**，另有 **4 次连接失败尝试 usage 未知**。没有配置完整单价，费用保留为 `null`。成功补跑的输入 token 总量高于修复前失败任务，不能声称本轮同时证明 token 成本降低。网络偶发连接错误也尚未解决。
