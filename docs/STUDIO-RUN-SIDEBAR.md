# Trace Studio 运行记录侧栏

原有 LongSeq、Ultrafast 在主内容顶部各有一个下拉框，Autoresearch 则在内容中另放研究列表。
切换 trace 的入口随视图改变，而且需要越过启动表单才能找到。现在由 Studio 外壳管理一条
**共用、可收起的左栏**，当前视图决定其内容：

| 视图 | 左栏内容 | 选择后的目标 |
| --- | --- | --- |
| LongSeq | `/api/runs` 的任务轨迹，显示任务、状态和时间 | `/?run=<id>`，滚动到轨迹画面 |
| Ultrafast | `/api/ultrafast/runs` 的原版运行，含 SaaS-Bench 轨迹 | `/ultrafast?run=<id>`，滚动到轨迹画面 |
| Autoresearch | `/api/studies` 的研究；选中研究时列出各轮任务轨迹 | `/research?study=<id>`；任务直达 LongSeq trace |

桌面侧栏宽 256px、随页面滚动保持可见；收起后主区恢复整幅宽度。窄屏默认关闭，
按钮打开 320px（不超过 86vw）抽屉；可点遮罩、关闭按钮或按 Esc 收起。
桌面的展开偏好存于浏览器本地。搜索只筛选当前列表，切换视图后清空查询，避免旧条件
导致另一视图看似没有记录。列表自动刷新，保留键盘焦点；选中项有文字和边框标记。

主视图既有下拉框仍在 DOM 中维持原有启动和轮询状态，但不再显示；选择和深链接仍经
各视图原有的 `navigate()` 处理。这样运行中的任务、草稿和浏览器历史不会因增加侧栏而重启。
侧栏使用现有只读 API 和 `textContent` 渲染记录字段，没有新增服务端读写路由。

SaaS-Bench 运行在左栏显示官方通过、未通过或评分无效。LongSeq 与原版 Ultrafast 的详情
共用判分卡片：严格成功、官方部分得分、Agent 状态和可展开的检查项分别展示。
上游评分器抛异常时，卡片明确写“评分无效”，原始分数仅供排查，不纳入成绩。
原版 Ultrafast 的判分卡片从其对应的归一化 benchmark 报告读取；服务端校验输出路径
仍在本地 runs 目录，并要求报告中的任务 ID 和原始 trace ID 一致。

验证：Mac mini 上的浏览器测试覆盖搜索、三视图切换、研究任务直达 trace、
URL/浏览器历史、收起偏好和 375px 抽屉；已用实际 SaaS-Bench 轨迹检查桌面和手机截图。

LongSeq 回放可使用 `/?run=<id>&replay=1` 打开：关闭自动跟随，从首个事件开始，
隐藏任务启动表单和长篇结果。点击“从头回放”播放，默认每 2 秒展示一个指令或执行动作，
跳过两者之间的等待；也可选择实时 1×、5× 或 20×。原始事件、时间戳和截图不变，
拖动时间轴及上一/下一事件仍可检查全部事件。

截图右侧始终展示选中时间点之前的最近有效 Brain `next_goal`、该指令指定的输入值，
以及最近真正执行的动作、实际 `bound_value` 和回执。候选、输入绑定和 `action_started`
不算已经执行；新指令发布后，上一动作仍标明其原指令，可展开核对，防止误配。
工作记忆可展开查看；没有动态 feedback 的旧轨迹回退到规划契约或原始任务。
动作回执的 `ok` 与官方 benchmark 成功分别展示。

这次回放新增功能使用 macmini 上的离线 JavaScript 检查和只读 HTTP 检查验证；
浏览器工具的 URL 安全策略阻止自动打开实际回放页，因此未完成此次视觉核验。
