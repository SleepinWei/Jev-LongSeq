# Browser use 长任务评测计划

以下是拟开展的研究，不是本次已经完成的模型实验。

## 任务设计

主任务分四类，每类独立调参考长度和依赖跨度：

| 类型 | 示范任务 | 终态判定 |
|---|---|---|
| 跨页搜集 | 逐页查看目录，读取详情，仅将符合条件的记录加入清单 | 清单集合精确匹配；无误加/漏加/重复 |
| 跨站核验 | 在站点 A 发现候选，到 B 核验属性，再按条件回到 A 筛选 | 候选-证据对应正确；满足所有约束 |
| 表单/业务流程 | 读取工单条件，查询资料，更新字段，再读回确认 | 正确记录的正确字段改变；其他字段不变 |
| 失效与恢复 | 弹窗、迟到结果、排序重排、会话失效、点击结果不明 | 恢复完成；无重复副作用；不能恢复时正确升级 |

例子都是任务模板，不是可直接运行的公共 benchmark task ID。当前 demo 只覆盖第一类的简化版本及初始弹窗；反复处理记录不足以证明深层规划能力。

先做约 30–40 个人工可复核 pilot，再扩展为 4 类 × 3 个长度档 × 10 个模板实例 = 120 个开发任务。
正式测试另建结构/实体/措辞 holdout；模型和阈值不得用测试集调参。每个测试任务重复 3 次；可靠性 pass^4 另用 4 次独立运行评估。
参考长度用人工/脚本正确解的原子动作数分档，例如 10–20、21–40、41–80、>80。实际步数单独报告，失败绕路不能提升“任务长度”。
H（长度）、D（依赖跨度）、L（无关页面信息）分别变化。增加浏览等待时间不等于增加长程推理难度。

## 公共 benchmark 优先级

1. MiniWoB++：定位、输入、下拉、滚动等小技能检查；不作为长任务主证据。
2. WebArena：常规浏览器端到端操作基线；从这里验证适配器。
3. **WebChoreArena：主实验。** 532 个任务强调大量信息处理、计算与跨页面长期记忆；固定其实际 release/commit 和任务清单。
4. WorkArena++：企业表单/工作流应用时加入，先确认 ServiceNow 实例与访问条件。
5. Odysseys：真实开放网页的长期、多站点任务；做后期外部效度检查，不与可重置环境混算。

BrowserGym 提供 WebArena、MiniWoB、WorkArena 等环境接口；WebChoreArena 用其项目代码/适配方式，不能假设安装 BrowserGym 就自动装好所有环境。
真实站点会随时间变化；记录观察日期、URL 和证据，并单列站点不可用/认证/挑战问题。

## 主指标

- **Strict Success Rate**：正确最终状态且无硬约束违规。分别报告每个长度档与任务类型。
- **Cost per success**：全部运行成本（包括失败）之和 / 成功数。包含所有规划、Jev、抽取、grounding、重试及浏览器成本。
- **End-to-end latency**：任务级 p50/p95，区分成功、失败、超时；API latency 不等于总 latency。
- **约束违规和重复写入**：对有副作用任务单独报告，不用平均成功掩盖。

## 诊断指标

- 信息搜集：实体/字段 precision、recall、字段准确性、来源可追溯率。
- Candidate Recall@K：人工标注/环境可行动作集合中的至少一个正确动作是否在候选里。允许多条正确路径。
- Grounding rejection：过期、找不到、被遮挡、歧义等；区分决策错误和执行错误。
- False completion rate：错误终止申请数 / 全部终止申请数；同时给出每任务概率。
- Recovery rate：遇到预先定义的可恢复故障后成功的任务比例。没有遇到故障的任务不进分母。
- Planner/Jev/vision call counts、token usage、平均子任务长度、每子任务验证成本。
- Return/revisit overhead：仅对确认冗余的重复访问计数；必要的核验回访不视为失败。
- 对独立标注事件的 Brier/ECE 和风险—覆盖率；不要把 Choice confidence 当实际成功概率。
- 采集/汇总型任务可用 rubric progress 补充，但有副作用任务不得以“多数步骤完成”取代严格成功。

## 必要对照

A. Flat Jev。
B. Flat Jev + 同等结构化记忆/检索。
C. 一次性规划 + Jev。
D. 事件规划器 + Jev。
E. 同一事件规划器 + 小生成式 LLM。
F. 强 LLM 每一步执行。
G. 规则执行器（可规则化的任务）。

条件允许时复现 WebDART 或相近动态分解基线，避免仅对弱基线比较。
D 与 B 区分时间分层和上下文整理；D 与 E 区分 Jev 和通用小模型；D 与 F 区分成功率与成本。

主实验共享 DOM/AX观察、候选生成、工具、验证器、权限和预算；原生 Browser Use Agent 的自由动作/视觉模式应作为另一实验轨道。
共享记忆的抽取和参数生成成本计入总成本。跨预算画质量—成本 Pareto 曲线，不只报告最有利的单点。

## 统计与验收建议

任务级配对对比；多次运行按任务聚类 bootstrap 95% CI。锁定模型版本、prompt hash、bench commit、故障配置、浏览器 viewport。
短任务开发后在更长 horizon 上测试；故障按相同业务事件触发，不能依赖两条轨迹已经分叉后的调用编号。
所有失败都保留，不从成本分母前先删除失败尝试。

拟定而非实测的项目目标：长任务比 B 提升 ≥10 个百分点；相对 F 在 −2 个百分点的非劣边界下降低每次成功成本 ≥30%，且不增加违规。最终阈值应结合业务风险与实验功效预注册。
